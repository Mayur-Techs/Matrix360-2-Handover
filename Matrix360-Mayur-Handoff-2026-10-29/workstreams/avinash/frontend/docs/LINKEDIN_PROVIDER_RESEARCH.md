## Provider contract

`lib/m360-linkedin-provider.js` exports `createProvider(config, fetchImpl)` and `ProviderError`. Dependency injection is used only by labelled tests. Production defaults to real fetch and fixed LinkedIn endpoints.

Configuration: `LINKEDIN_CLIENT_ID`, `LINKEDIN_CLIENT_SECRET`, `LINKEDIN_REDIRECT_URI`, `LINKEDIN_API_VERSION`, `LINKEDIN_SCOPES`. The implemented API version defaults to **202610**, a version present in current official documentation. Version 202511 sunsets on November 16, 2026; it is deliberately not copied from old examples. Version remains configurable for migration. All `/rest` calls include `LinkedIn-Version` and `X-Restli-Protocol-Version: 2.0.0`. [Posts documentation](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/shares/posts-api?view=li-lms-2026-10).

| Method | Return / responsibility |
| --- | --- |
| `authorizationUrl(state)` | LinkedIn consent URL; caller owns one-time, session/workspace-bound state storage |
| `exchangeCode(code)` | Server-only access token, optional refresh token, actual `scopes[]`, ISO expiries |
| `refreshToken(refreshTokenString)` | Exchanges an actually issued refresh token; returns confirmed scopes/expiry and preserves the supplied refresh credential if not rotated |
| `introspect(token)` | Provider-confirmed active grant and scopes |
| `identity(token)` | OIDC member `id`, `urn`, `name`, optional `picture` |
| `destinations(token, scopes)` | Connected member plus operation-verified eligible Pages; independent capability flags |
| `checkAuthority(token, destination)` | Rechecks active grant, actual publication scope, member identity and Page organic authority |
| `uploadMedia(token, author, {kind,bytes,mime,title})` | Real media URN and returned processing status after acknowledged upload |
| `mediaStatus(token, media)` | Real processing status; `STATUS_UNAVAILABLE` if grant cannot read status |
| `publish(token, {author,text,media,link})` | Real `x-restli-id`, derived LinkedIn post link, provider acknowledgement |
| `readPost(token, id)` | Actual authorized read-back; no inferred verification |
| `metrics(token, {author,id,scopes})` | Actual available values, ISO retrieval time; unavailable values remain null |

`ProviderError` exposes code, HTTP status, retryAfter seconds, retryable and uncertain. It does not expose upstream bodies that could contain customer content or secrets.

## OAuth and capabilities

- Authorization: `GET https://www.linkedin.com/oauth/v2/authorization`; exchange: form-encoded `POST https://www.linkedin.com/oauth/v2/accessToken` with code, redirect URI and application credentials. Actual scope returned by exchange is retained. If omitted, `POST /oauth/v2/introspectToken` confirms the grant; requested scope is never substituted as evidence. Introspection scope is comma-separated; exchange scope may be space-delimited. [OAuth](https://learn.microsoft.com/en-us/linkedin/shared/authentication/authorization-code-flow), [introspection](https://learn.microsoft.com/en-us/linkedin/shared/authentication/token-introspection).
- Identity: `GET https://api.linkedin.com/v2/userinfo` with `openid profile`. Successful OIDC login alone does not grant publishing. OIDC identity is not identity verification. [OIDC](https://learn.microsoft.com/en-us/linkedin/consumer/integrations/self-serve/sign-in-with-linkedin-v2).
- Default requested scopes are `openid profile w_member_social`. Request additional scopes only after the app has those products enabled. Personal publishing uses `w_member_social`; reading personal posts requires the separately restricted `r_member_social`. Organization publishing/reading use `w_organization_social` / `r_organization_social`.
- Page discovery uses paginated `GET /rest/organizationAcls?q=roleAssignee&state=APPROVED`. This adapter requires `rw_organization_admin` for discovery and operation checks; it does not claim support for Page connections without that entitlement. Organic create authority uses `GET /rest/organizationAuthorizations/(impersonator:{person},organization:{organization},action:(organizationContentAuthorizationAction:(actionType:ORGANIC_SHARE_CREATE)))` and requires a provider Approved status. [Access control](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/organizations/organization-access-control-by-role?view=li-lms-2026-10), [operation authorization](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/organizations/organization-authorizations/organization-authorizations?view=li-lms-2026-10).
- Access tokens expire. Refresh tokens are returned only for entitled applications. `refreshToken()` uses form-encoded `POST /oauth/v2/accessToken` with `grant_type=refresh_token`. The caller controls renewal timing and must preserve the original refresh expiry if the response omits it; refresh does not reset the original credential lifetime. Expiry/revocation requires reconnect. [Refresh access](https://learn.microsoft.com/en-us/linkedin/shared/authentication/programmatic-refresh-tokens).
- Matrix360's commercial app needs the applicable LinkedIn review, verified business email, legal organization details, website/privacy policy and Page-super-admin verification. These owner actions cannot be replaced with an environment toggle. [Community Management review](https://learn.microsoft.com/en-us/linkedin/marketing/community-management-app-review?view=li-lms-2026-10).

## Media, publication and recovery

- Images: initialize `POST /rest/images?action=initializeUpload`, PUT actual bytes to returned upload URL, read `/rest/images/{encodedURN}`. JPG/PNG/GIF are documented; fewer than 36,152,320 pixels, GIF up to 250 frames. The adapter MIME-checks; provider processing is the ultimate format/dimension authority. Versioned image GET is unavailable with only `w_member_social`. A successful upload followed by status-read 403 is represented as `STATUS_UNAVAILABLE`, not AVAILABLE. Publication may then be attempted and LinkedIn decides media eligibility. No synchronous readiness is fabricated. [Images](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/shares/images-api?view=li-lms-2026-10).
- Video: initialize `/rest/videos?action=initializeUpload` with owner, exact size, and caption/thumbnail flags; PUT each inclusive byte range; collect ETags in order; finalize `/rest/videos?action=finalizeUpload` with video URN, upload token and ordered part IDs. Read `/rest/videos/{encodedURN}` until AVAILABLE; persist PROCESSING for a later pass. Reject invalid/incomplete/overlapping ranges. The current documented non-CTV specification is MP4, 75 KB–500 MB, 3 seconds–30 minutes. The provider adapter enforces byte-size bounds; full decoding/duration remains provider processing validation. Matrix360's upload-service 200 MB video limit is a local resource bound. [Videos](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/shares/videos-api?view=li-lms-2026-10).
- Documents: initialize `/rest/documents?action=initializeUpload`, PUT bytes, read status. LinkedIn permits PDF/PPT/PPTX/DOC/DOCX up to 100 MB and 300 pages. Matrix360's upload service currently exposes PDF; adapter recognizes the documented MIME types. Page count is ultimately checked by provider processing; no local PDF parser was added. [Documents](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/shares/documents-api?view=li-lms-2026-10).
- Text/media/link publication uses `POST /rest/posts`; PUBLIC visibility, MAIN_FEED, no named target recipients. Media uses returned media URN; links use article source. Only a real valid `x-restli-id` yields accepted=true. An ID-derived URL is a navigation link, not read-back proof. Native sponsored carousel, polls, multi-image, reshares and comments are outside this adapter's current methods.
- No POST is automatically retried inside the adapter. Missing post ID, transport failure during publish, and publish HTTP 5xx are uncertain. Explicit 429 rejection returns Retry-After for the worker. Internal idempotency does not establish exactly-once LinkedIn publication. Caller must persist acknowledgement before subsequent reporting and reconcile unknown outcomes manually when read access is absent.
- Upload destinations must be HTTPS LinkedIn/licdn hosts; redirects are rejected. Signed licdn uploads do not receive the bearer token. No browser cookies, private LinkedIn endpoints or browser automation are used.

## Reporting and data boundaries

- Member statistics: `GET /rest/memberCreatorPostAnalytics?q=entity&entity=(share:{URN})` or `(ugc:{URN})`, with `queryType` and TOTAL aggregation; requires `r_member_postAnalytics`. Adapter retrieves impressions, members reached, reactions, comments and reshares. Missing count is null. [Member statistics](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/members/post-statistics?view=li-lms-2026-10).
- Page statistics: `GET /rest/organizationalEntityShareStatistics?q=organizationalEntity&organizationalEntity={URN}&shares=List(...)` or `ugcPosts=List(...)`; requires `rw_organization_admin` and eligible administrator. Organic statistics use a rolling 12-month window and exclude paid activity. [Page statistics](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/organizations/share-statistics?view=li-lms-2026-10).
- Comments, Ads and Lead Sync require their own enabled product/operation. A capability scope flag is grant information, not proof that Matrix360 implements that feature. This adapter does not send invitations, DMs, InMail or paid campaigns, nor ingest engagement as CRM contacts.
- LinkedIn Community Management member data cannot be used to create/enrich prospects or audience lists. Third-party API content cannot be input to generative content/reply creation; the AI policy distinguishes permitted classification/accessibility uses and app users' own content with applicable consent. Matrix360 drafting should use independently client-supplied brand facts/assets, not retrieved third-party comments. [Restricted uses](https://learn.microsoft.com/en-us/linkedin/marketing/restricted-use-cases?view=li-lms-2026-10), [Developer AI Policy](https://learn.microsoft.com/en-us/linkedin/marketing/developer-ai-policy?view=li-lms-2026-10).
- Retention is source-specific: authenticated member profile/URN has no fixed duration in the published table; authenticated Page profile 8 weeks; Page reporting one year; other member profile cache 24 hours; member social content 48 hours. Independently client-supplied data is excluded from this table. The provider does not persist returned data; service/storage owns retention and deletion. [Storage requirements](https://learn.microsoft.com/en-us/linkedin/marketing/data-storage-requirements?view=li-lms-2026-10).

## Optional product rules versus API requirements

Matrix360's separate review step and media-rights checkbox are configurable product workflow choices. Actual customer OAuth consent, granted scope, current Page authority, valid tokens, format constraints and platform responses remain real provider requirements. Workspace isolation, token encryption, OAuth state binding and duplicate prevention protect the requested SaaS's correctness; they are not extra customer marketing opt-ins. Organic posts do not require a recipient consent list because they are not directed deliveries. No email or WhatsApp rules were inspected for changes or modified by this work.

## Verification and remaining limits

`node --test tests/linkedin-provider.test.js tests/linkedin-api.test.js` passed **17/17** tests. Twelve provider tests cover actual-scope fallback, refresh/rotation/expiry, wrong author/revocation, denied Page, multipart bytes/ETags, video bounds, hostile upload URL, unavailable media reads, acknowledgement, unknown outcomes, rate limits and missing metrics. Five API integration tests use the actual API/service/SQLite with declared fake CRM/provider transport to cover anonymous access, membership/roles with optional reviews disabled, methods, cross-site requests, guessed foreign IDs, worker authentication and independent encrypted grants for two tenants.

Live acceptance remains required for this app's scopes, OIDC subject/member URN correspondence, Page authorizations, actual media processing/limits, publication read-back and analytics availability. No customer data, real token, actual provider identifier or fabricated live evidence was used in these tests.

## Content Studio coordination

`lib/m360-linkedin-content.js` calls the existing `api/creative-media.js` internally with the current authenticated bearer and selected workspace. That handler's own membership checks, configured provider access and existing generation approvals remain unchanged. Start requests reserve a workspace-bound UUID before invoking generation, so retries and simultaneous clicks with the same UUID do not charge twice. Ambiguous starts remain unknown; no new provider job is silently created.

Polling uses the actual saved provider job. A completed image/reel is downloaded only from the handler's exact expected workspace/job path on its Social Manager host or private signed Supabase video archive. Downloads reject redirects, exclude bearer headers, and enforce bounded streaming. The bridge imports bytes through the same upload/chunk/completion service as client uploads, yielding a tenant-owned asset and hash. Signed URLs and session bearer tokens are never persisted. Import retries reuse the provider job; completed asset acknowledgement can recover after an interrupted request.

`node --test tests/linkedin-content.test.js` passed **8/8** real-SQLite/service tests with declared fake Studio/download transports. These cover concurrent idempotency, uncertain start, pending versus actual completion, two tenants, hostile URLs, retrying only import, oversized output and interrupted completion recovery. No real generation or paid provider invocation occurred. End-to-end generation still depends on the existing Social Manager service and provider configuration; this bridge does not establish that remote service's availability or production readiness.
